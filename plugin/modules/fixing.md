## Fixing — evidence

(Capability-patch cohort. Loaded by every session and subagent
tier: entries retire on fire-rate evidence — a class no tier still
needs — not on top-model upgrades alone.)

- A defect report locates a symptom, not the change. Fixes at the
  symptom site before the root cause is articulated spiral; the
  reported symptom never reliably sets the scope. Articulating the
  cause does not finish the question either: it admits several
  CORRECT changes, and which one survives is decided by the system
  being changed — never by taste, never by the reasoning that
  found the cause. So the system's EXISTING instances of the
  concept are read before the change is written, and they bind on
  two axes measured against one upstream. WHERE: a one-line
  zero-fill at ALLOCATION was declined, and the owner later fixed
  the identical defect at the READ, masking invalid rows two lines
  under a validity mask the function already built for another
  purpose — the change that holds sits where the invariant is
  CONSUMED, reusing what that site already computes, while the
  distant one leaves a rule nothing at the point of use enforces
  and pays wherever the source is expensive. WHAT SHAPE: a feature
  PR was declined as "redundant settings (for instance scale and
  scheduler)", a second implementation of concepts the system
  already carried — existing instances fix the layering, the
  names, the idiom, and preferences stated nowhere but in the code
  itself. Neither axis is bounded by ownership or by these two
  shapes: the same read is owed inside one's own repo, where a
  session built a whole parallel checker beside contract machinery
  that already existed and one grep would have found (JOURNAL, fix
  placement and shape, 2026-09-07). Compose-time tell across both:
  the change introduces a concept its site did not already have.
  Distinct from where wrongness is FOUND (below) — that rule
  places the CHECK, this one places and shapes the CHANGE.
  Convention: a change names the existing instances it was read
  against — the site whose invariant it serves, and what already
  present there it reuses; one that reuses nothing states what it
  read and why nothing fit, which is how a genuinely novel
  addition passes without the rule softening.
- Bundled changes hide which edit did what — a diagnosis fact,
  scoped there. Expensive per-round verification (a fresh-context
  review, a round trip through another party) prices the opposite
  way: a round run over a state already scheduled to change grades
  a stale object, so decided-but-unbuilt changes land before the
  round, per-change attribution kept by each change's own checks.
- What was DONE is read off the object, never off the memory or
  the report of having done it. "Fixed" without the verifier's
  output is repeatedly wrong, and the verifier's output is what
  the check itself wrote, never an intermediary's exit status:
  launchers, schedulers, and background-task notifications report
  that the run happened, not what it found. A prior step's EFFECT
  diverges from the memory of it two ways, and only one announces
  itself: the step was BLOCKED — a gate, a guard, a refused
  permission — and left nothing where its successor assumes
  something; or it succeeded and another writer has since changed
  the shared object, leaving more than memory holds. The successor
  is where the damage lands: an undo sized to "the thing I just
  made" deletes real work when nothing was made, and deletes
  others' work when something was added (observed as a reset
  destroying a real commit after an unread hook denial, and as a
  created file deleted with another writer's entries meanwhile in
  it). What sizes a destructive or irreversible step is the
  object's CURRENT state, never the intent to have caused it. The
  same drift binds
  the step HANDED to another executor: a procedure answering "how
  do I undo/disable X" runs at a time its author does not choose,
  and a recipient never told a precondition exists cannot check
  one — least of all an operator, holding no protocol the sender
  can lean on (peer instantiation, receiver side: Model routing,
  state-dependent directives). Where X is currently load-bearing,
  the condition that makes the procedure safe travels IN it: the
  how-question is not the whether-question, and only the answerer
  sees the whether.
- Re-derivation is evidence-gated, in both directions. Settled
  ground re-opened without new evidence burns sessions — past a
  few turns of investigation, the on-disk ledger (see Insurance)
  is what keeps it closed. New evidence that kills a premise does
  not revoke what was derived from it: plans and conclusions built
  on the old premise execute stale unless enumerated and
  re-derived from the current record (the stale-premise class).
  The tell is a premise and its dependent contradicting inside one
  output.
- Wrongness lives where the work takes effect — the stored data,
  the running system, the delivered output — and only checks at
  that altitude find it; reviewing what produces the effect is not
  checking the effect. Reconstructing behavior from the source is
  the same error one level down: every claim from modelling the
  system was wrong, every claim from executing it survived. The
  rule under-fires on the INVERSE
  claim — "this check never runs", "nothing guards this path" — a
  behavior claim in structural clothing: verifying the structural
  half certifies that half only, while the consequence drawn from
  it ships unchecked wearing the same confidence. A scoped read
  never settles an unscoped absence. The claim predicts an effect,
  so the counter for that effect is the probe — a zero where the
  claim requires non-zero refutes it. Where a question is
  answerable by exercising the real system on real inputs,
  reasoning about it is not a cheaper path to the same answer.
  Where it cannot be exercised ON DEMAND — an intermittent,
  externally triggered, or self-destroying event — the rule
  changes instrument rather than lapsing: a recorder at the effect
  site, and the next occurrence answers. The record already in
  hand is the one that has ALREADY failed to answer, so each
  further round over it is priced in occurrences of the harm —
  and those rounds are the ones that feel free. Compose-time
  tell: a second pass over the same log. Where
  exercising it costs a round trip through another party — an
  operator-run command, a CI run, a remote executor — the unit of
  exercise is not one candidate but a BATTERY whose outcomes
  separate the live hypotheses, at the same single trip's cost
  (JOURNAL, wrongness at the effect site, 2026-08-26).
  Compose-time tell: what crosses to the other party is a fix
  rather than a measurement. A PROCEDURE crosses under the same
  rule and escapes it by not presenting as an experiment: finished
  instructions read as a deliverable, so nothing asks what was
  exercised. One step needing the RECEIVER'S AUTHORITY is what
  blocks exercise — never the procedure's other steps — yet the
  boundary around that step becomes an exemption for all of them.
  Convention: what crosses is exercised first — every step not
  gated on that authority, in the RECEIVER's environment rather
  than the sender's (a name resolves on their search path, not
  yours), the unexercisable remainder — or its absence — named as
  such in the same message (site facts for the two executors here:
  Shell and privilege).
  One's own past output is the same altitude question, at the
  claim moment only, and in EVERY direction and quantity: "I
  already answered/sent/delivered X", "I never said Y", "that was
  the only one", "three of them" — each is a claim about the
  transcript, checked there (a seconds-cheap search) before it is
  asserted, never answered from memory; routine recall is
  untouched. The negative and the COUNT are the under-served
  halves: a denial and a tally feel like recollection rather than
  like claims, so nothing prompts the look. Work-product surviving
  (a commit, a booking) while its delivery was aborted leaves a
  memory of having communicated that the record refutes. The
  transcript settles the LINEAGE's act, never this process's: a
  resumed or forked session inherits the record along with the
  memory, so the prescribed check returns a confident true for
  every process sharing one — symmetrically, which is why nothing
  prompts a second look. Where the claim's consequence needs a
  LIVE actor — a delivery, a push, a message that must arrive, a
  lock still held — the discriminator is the process itself (its
  own ancestry, one call), then the world: the remote, the
  artifact, the receiver's acknowledgement.
- What a check anchors to must be immutable, and the anchor fails
  in TWO directions of which only one announces itself: criteria
  anchored to live, mutating state decay into false alarms, while
  the same drift in the quiet direction leaves the check PASSING
  while it exercises less than it claims. What drifts is the
  check's PREMISES — everything it depends on but does not itself
  establish: a fixture's shape, a file's absence, a search
  pattern's reach (observed as a case green only because a store
  file did not exist on that machine, a zero-hit grep whose phrase
  wrapped across a line break, and fixtures built under a
  two-valued predicate that routed silently through the third once
  one was added). A premise the check does not pin
  is one the environment is free to satisfy today and not
  tomorrow; pinned INSIDE the check, frozen into a fixed
  reference, both directions stay re-runnable. The worst case is
  an instrument whose output is SILENCE — a wait, a poll, a
  watch — where both failures are indistinguishable from working:
  a condition read off CUMULATIVE state is satisfied by whatever
  predates the wait and fires instantly having observed nothing;
  an anchor resolved ONCE at arming keeps watching a name its
  target has vacated and reports nothing forever. Waiting looks
  identical either way, and a throwaway loop never presents as an
  instrument at all (observed as a container name captured before
  the container was replaced, a log window read from a process too
  young to hold one, and a wait keyed to a cumulative match a
  boot-time line already satisfied). A wait means something only
  where its
  anchor is resolved inside each pass and its condition keyed to a
  DELTA from a baseline taken when the wait began, or to a marker
  that cannot predate it — and the baseline is its own positive
  control: a wait whose baseline resolved to NOTHING is dead at
  arming and reads exactly like a lane that has not moved yet, so
  the arming output shows the resolved value (measured 2026-08-27:
  an unquoted variable under zsh gave git one nonsense path, the
  baseline came back empty, and every pass compared empty to
  empty). The pin has a boundary: it covers
  ENVIRONMENT
  premises, never the graded source's own extent — a coverage
  assertion whose comparison basis is RESTATED from the source it
  grades (a hardcoded list beside the parser it mirrors, a copied
  enum) cannot age loudly: the source gains a member and the
  assertion stays green, byte-identical to health. That basis
  derives from the source wherever it is queryable, and from the
  RUNNING parser rather than a scan of its text — a source
  building half its members from a loop variable under-counts
  under any scan (measured, n=2: a planted extra lane invisible
  under the restated set, red under the derivation). Where a
  predicate
  GAINS a value, every existing case is re-asked which value it
  now exercises — a fixture written for the old predicate does
  not fail under the new one, it stops testing. The cheap
  instrument across the class is an assertion on what must NOT
  appear in the output: it catches a check DEGRADING where a
  presence-assertion catches only one breaking
  (JOURNAL, what a check anchors to, 2026-08-26).
- Confirmation reads do not catch what refutation probes catch. A
  load-bearing claim earns one probe designed to DISPROVE it — a
  check whose positive result would kill it — before work rests on
  it (same ground as the briefed-to-refute rule under Insurance).
  Load-bearing includes DELIVERED: a claim shipped as fact in a
  report — or an explanation given to the operator in
  conversation, which is where their model of the system comes
  from — is rested on by its reader; casual prose is the costume
  drawing least scrutiny. Naming the contrary fact is not probing
  it: a hedge that states the disconfirming result and explains it
  away — not yet exercised, latent — buys the feeling of
  refutation while the claim stays untested, and it reads as rigor
  to its author, which is why nothing prompts the second look.
  Severity raises the evidence bar, never the speed of delivery.
  - **Non-events.** A claim the work goes on to execute (parse,
    run, render) breaks loudly as a side effect of building —
    except where the expected result is a NON-EVENT (nothing
    changed, the count held, no finding): a dead mechanism yields
    that too, so the probe is disabling the mechanism against
    real input and watching the difference appear. A SEARCH that
    finds nothing — over one's own work or someone else's
    artifact — is that same non-event in discovery's clothes: a
    pattern that could never have matched returns exactly what a
    true absence returns. Absence is claimable once the
    instrument is shown live on a known positive — the same
    pattern matching a case that IS present, or a planted one.
    Self-chosen search terms are the instrument, and their reach
    is the claim's basis. A failure to REPRODUCE is the same
    shape in a third costume — not-observed read as not-there. It
    arrives while checking a measurement someone else reported,
    where the negative also confirms the checker's doubt, so
    nothing prompts a second look; there the SETUP is the
    instrument — an arrangement that could not have produced the
    reported effect returns exactly what a genuine refutation
    returns — so the reported conditions (scale, environment,
    ordering) are reproduced before a negative counts as one.
  - **Prose-only claims.** A claim that ships only in prose is
    exercised by nothing — a building-heavy stretch verifies most
    of its claims as a byproduct while a pure report verifies
    none. That asymmetry is the trap: the executed claims around
    it answer "which one was never executed?" by feel, and the
    survivor is rarely the finding — it is the mechanism the
    finding rests on (how the surrounding system behaves, why the
    fix is the right shape), which reads as background rather
    than as a claim. At delivery, the identifying question: which
    sentence, if false, would change the recommendation — and was
    THAT one executed? What feels known without looking is where
    it hides. Convention: the delivered mechanism- or causal-claim
    names its executed check the way a verdict names its basis —
    absent one, it ships labeled "unverified".
  - **Definitions.** What counts as correct comes from the
    DEFINITION of the thing checked, never from the artifact
    under test or the reasoning that produced the claim. A
    wrongness claim — the artifact is buggy, corrupt,
    misconfigured, incorrect — asserts a deviation from its
    definition. Exercising the artifact grounds only the behavior
    half: reproduction shows what it does, never what it is
    supposed to do. The supposed-to half only the definition
    answers — for an installed artifact it sits at reading
    distance, not reasoning distance; unread, the claim carries
    the label "unverified". A document about the artifact is not
    its definition — notes drift, the artifact does not. A design
    premise ("X lacks Y", "X mislabels Z") is the same claim in
    solution clothing, inheriting the same probe.
  - **Instruments: discrimination and reach.** The INSTRUMENT
    earns the same probe — instrument meaning any producer of a
    verdict or measurement the work rests on: a diagnostic, a
    printed number, or a pre-registered decision criterion as
    much as a test. It is unproven until it has gone red on the
    defect it was built for, and an assertion's discriminating
    power is measured against that DEFECT, never against change:
    one both the correct and the defective behaviour satisfy is
    unproven whatever it asserts. "The two must DIFFER" is the
    recurring form — it separates something-happened from
    nothing-happened where the question was WHICH outcome
    happened, so could-not-verify passes as verified-wrong.
    Discrimination takes a PAIR: the probed result equals the
    outcome the probe NAMES (falsifiable by the defect), and
    differs from the unprobed one (catching a probe that missed
    its target and left the check reading real input). Reach is
    settled at ARMING, not only after a red: an instrument
    watching for an EFFECT is keyed to particular routes into it,
    and a route it does not watch returns exactly what a true
    absence returns — so the enumeration comes from the system's
    own list of what produces that effect, never from the
    mechanisms that came to mind while building. Naming the
    instrument for the effect while it watches one route is the
    assurance wider than its predicate (Grounding, the
    mechanism's label). A STAGED instrument narrows one stage at
    a time and its control inherits the narrowing: a control
    proves only the stages it PASSES THROUGH, so one injected
    below the stage under suspicion returns exactly what a sound
    chain returns, and its green reads as a green for the chain
    while the narrowing sits upstream of where the control
    entered. The control enters at the chain's TOP, or the claim
    names which stages went unexercised — a yield reported off a
    mid-chain green is the suffix's yield wearing the whole
    chain's costume (JOURNAL, staged control, 2026-09-14).
    Red certifies the CLASS that fired,
    not the instrument's reach: a variant of the defect needs its
    own positive, and instruments sharing an author repeat one
    blind spot across the set — the authorship that matters being
    the PAYLOAD's as much as the code's. Divergence between two
    independently built measurements of the same quantity is the
    cheap reach detector; a lone instrument's green is
    indistinguishable from its blind spot. Agreement is the weaker
    half: two measurements certify nothing about an axis NEITHER
    varied. The shape that hides it: the fixed property is the
    very trigger of the mechanism under test, so holding it fixed
    reads as the obviously correct probe to each builder
    independently. Convention: a corroborating measurement names
    the axis it VARIED; where both held one fixed, the agreement
    is could-not-verify on that axis, never confirmation. Two
    measurements only compare where they share a
    COORDINATE, and agreement on the verdict hides its absence: that
    an item is a defect means nothing if the two name different items
    by the same index (JOURNAL, instruments, 2026-08-26). Without the
    shared coordinate established first, the comparison is
    could-not-verify, never agreement. A red arriving for a reason
    nobody planted is a finding about the ARTIFACT, not breakage in
    the test: repairing the test to restore the expected red converts
    a live finding into a silenced instrument. A criterion's red is a
    DRY-RUN against cases already in hand — real ones, plus a
    constructed case each outcome would misclassify: a criterion
    booked unexercised sharpens on first contact, and that first
    contact arriving as an operator question is the recorded miss
    shape. Red is established by running the NEW expectations
    against the OLD implementation, and the arrangement producing
    it is itself checkable. Reverting the working state to reach
    "old" removes the new expectations along with it, so old runs
    against old and passes vacuously — a green that means
    nothing, reported as proof; the arrangement is the basis —
    which side was old, and where the expectations came from.
    The BASELINE is part of that arrangement: a red-first proof
    runs the unmutated case first and states its result, because
    over an already-red baseline a mutate-and-revert proof is
    indistinguishable from a check that is simply always red — a
    baseline assumed green is an unverified premise in a
    verification's costume.
  - **Parentage.** What an expectation — an assertion, a decision
    criterion, the derivation behind a printed number — is derived
    FROM decides whether it can catch anything; the instrument
    inherits this rule whole. A same-parentage expectation
    pins the very defect it should catch — writing the definition
    before the assertion is what surfaces the contradiction — and
    "it would have caught this" is the same unverified reasoning
    it exists to replace. Deriving the expectation from the
    artifact is that error only where the artifact is the
    SUBJECT: where the question is whether two PEERS agree, each
    side read independently from its own home is the method, and
    reading one side off the other is what makes the comparison
    vacuous — while an expectation derived from the artifact it
    GRADES moves with the mutant and stays green on the
    corruption it exists to catch. The discriminator is whether
    the artifact is one of two sides or the thing on trial. A
    SPEC is a parent too. Two of its sentences disagreeing — a
    design sentence and the verifier sentence meant to enforce
    it — is a parentage defect, and neither settles it from the
    inside: the deciding test is which reading FIRES on the
    motivating incident, measured against it. The reading that
    stays silent there ships a check reporting clean forever, and
    its correctness as a sentence is what hides that. The error
    also runs in reverse: a rule minted to RATIFY an existing
    mechanism's behavior derives the definition from the
    artifact — the tell is a rationale citing what the mechanism
    does rather than what the work requires, and the
    re-derivation is from the work's requirement, before rule or
    mechanism changes.
  - **Unprovable and over-firing checks.** Checkers pass review
    and catch nothing: a size statistic constant across the very
    bug targeted; an adjacent-only comparison skipping most of
    the pairs it was meant to compare — each reporting clean
    runs, and each readable before it ran. A predicate no input
    could falsify, or none could satisfy, is not unproven, it is
    unprovable. A check that fires on a NON-defect is failing
    too: a blocking assert on a hardcoded count stopped
    validating anything the day the count legitimately grew, and
    both left a reader trained to discount a red result. When a
    guard fires on legitimate work, the repair is a declared
    exemption the guard itself verifies — the legitimate case
    named in data it checks — never a softened predicate or an
    override habit.
- A cleanness claim — sanitized, scrubbed, redacted, contains no
  X — is a wrongness claim in mirror, inheriting the
  definition-derived absence probe (red-first, per the instrument
  rules above); the probe is due before the irreversible boundary:
  a red result after the act is a post-mortem, not a catch. Removal
  and construction price differently: a scrub deletes the hazards
  someone enumerated, and the unanticipated field ships by
  default, while an artifact built from known-safe parts ships
  nothing that was not deliberately placed. The boundary is not
  only OUTBOUND (publish, push, send): a READ can be the
  irreversible act — anything that pulls sensitive state into a
  durable context (an unmask or reveal flag, an env dump, a
  credentials listing) cannot be un-pulled, and it escapes the
  gate because reads present as inspection rather than as action.
  The question is what MINIMUM answers the ask — existence, a
  count, a masked listing usually does — and a SCOPING parameter
  does not bound a DISCLOSURE one: naming the one key you care
  about need not stop the response carrying every other (observed
  as a masked listing that had already answered the question, and
  a reveal that pulled an entire secret store into a session
  transcript).
- A manual investigation that produced a finding is unfinished
  while the check that would have produced it does not exist —
  the hand-derivation is the prototype, the mechanism is the
  deliverable: it finds the defect at the moment it occurs,
  without the reasoning that produced it — and that reasoning is
  exactly what does not survive into the next session (the
  mechanism bar, and the judgment remainder that stays prose:
  Calibration). The
  throwaway probe script is the tell that a check is missing. Two
  qualifiers, both learned by violating them: the check counts
  only once it has gone red on the real defect, and it must
  automate the MECHANISM rather than a remembered symptom — a
  check built from a number belonging to a different,
  already-fixed bug watches the wrong quantity.
- A result carries only the variables its run reproduced, and the
  gap is invisible in both directions. CONFIRMING: a prediction
  confirmed offline is not confirmed live until the live test
  holds every other variable fixed. EXCULPATORY: a suspect
  mechanism re-run clean is exonerated only for the variables the
  re-run reproduced — code, working directory, environment,
  invocation channel — and the unreproduced variable is where the
  writer hides (JOURNAL, variables reproduced, 2026-08-26).
  ATTRIBUTING: changing two things
  and attributing the result to the one that was predicted about
  reads as validation and is not — a restart that flipped three
  configuration gates at once paid a documented one-time cost
  belonging to one of them and settled nothing about the restart
  itself. The tell is a result equally consistent with the
  hypothesis and with the thing changed alongside it.
